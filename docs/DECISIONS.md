# 설계 결정 기록

## 2026-11-01 / 기존 Python 서비스 안에 스튜디오를 추가

목적은 현장의 AASX 작성과 수집을 연결하는 것이다. 기존 Modbus TCP/XGT 드라이버와 데모·연결 테스트를 재사용한다. 외부 호스팅의 HTTP 전용 런타임은 현장 TCP 통신을 대신할 수 없으므로 현재는 로컬 작업 공간으로 제공한다. 원격 서비스와 현장 에이전트 분리는 다음 아키텍처 단계다.

## 앱 프로필을 명시적으로 사용

모델의 외형이 AAS라고 해서 표준 IDTA 서브모델을 구현한 것은 아니다. 초기 단계에서는 잘못된 semanticId를 붙이지 않고 앱 소유의 프로필을 사용한다. 구조는 독립된 공식 JSON 스키마로 확인하되 그 결과를 전체 표준 인증으로 표현하지 않는다. 이후 공식 명판/인터페이스 템플릿을 별도 마이그레이션으로 구현한다.

프로필은 Blob으로 AAS Environment 안에 저장한다. 별도 임의 ZIP 파일만 읽는 방식보다 다른 AAS 도구가 프로필 존재를 확인할 수 있다. 표준화된 범용 연결 모델을 대신한다는 의미는 없다. 파일의 설비 ID/참조와 프로필을 대조하고 내보낼 때도 주소 입력을 재검증한다.

## 파일 생성과 수집 준비를 별도 상태로 표시

통신 미상인 설비도 식별 정보만으로 파일을 만들 수 있어야 한다. 수집 적용에는 주소·프로토콜·신호가 필요하다. 정보 부족을 임의 기본 매핑으로 메우면 사용자가 정상 연결로 오인할 수 있으므로 ‘파일 필수 / 수집 필수 / 권장’을 구분한다. 실제 현장 검증은 입력 검사로 완료 처리하지 않는다.

## 수집 설정은 충돌 없는 추가로 한정

적용 전 접속 경로·신호·주기를 보여주고 추가만 허용한다. 설비 ID에서 결정적인 이름을 만들어 중복/재적용을 검출한다. 기존 구성 checksum으로 미리보기 이후 변경을 검출한다. 저장은 기존 백업과 원자적 파일 교체를 사용한다. 실행 중인 수집에는 적용하지 않는다. 기존 항목 갱신/교체는 삭제 영향과 참조 관계를 보여주는 후속 기능으로 남긴다.

## 추천은 조건과 근거를 공개

센서 종류와 채널 수만으로 실제 호환성이 확정되지 않는다. 추천 결과를 ‘조건부 후보’로 표현하고 기존 경로, 입력 범위, 절연, 전원, 속도, 배선, CPU 슬롯/펌웨어를 확인하도록 한다. CPU 정보가 없으면 특정 LS 모듈 형번을 지정하지 않는다. 이 단계에서는 LLM이 하드웨어 사양을 생성하지 않고 명시적 규칙을 사용한다.

## 코드와 의도를 같은 Git 브랜치에 보관

대화 내용을 유일한 프로젝트 기록으로 삼지 않는다. `AGENTS.md`는 재진입 지침, `PRODUCT.md`는 제품 목적, 이 문서는 판단 이유, `HANDOFF.md`는 실제 현재 상태와 다음 작업을 담당한다. 코드·검증·문서를 함께 커밋/푸시하여 다른 PC에서 동일 브랜치를 받을 수 있게 한다. 실제 고객 데이터는 Git에 포함하지 않는다.
