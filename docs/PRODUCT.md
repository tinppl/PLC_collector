# 제품 목적과 사용자 경험

## 달성하려는 결과

현장 담당자가 AAS 구조를 공부하지 않아도 설비의 디지털 표현을 만들고, 실제 데이터를 수집하기 위해 필요한 정보를 정리할 수 있게 한다. AASX를 작성하거나 업로드하면 서비스가 알고 있는 연결 정보는 재사용하고, 모르는 부분은 필요한 확인 사항으로 남긴다. 추가 하드웨어가 필요한 경우 구매 이유와 적합성 확인 과정을 제공한다.

‘AASX 업로드 = 모든 설비 자동 연결’이라고 약속하지 않는다. AAS는 설비의 디지털 표현이며, 제조사별 레지스터 맵·접근 권한·현장 배선·네트워크 경로까지 항상 제공하는 것은 아니다. 자동화 가능 범위는 입력 정보와 검증 결과로 결정한다.

## 대상 사용자

- 설비 담당자: 설비 명판·IP·매뉴얼을 가지고 있으나 AAS 모델링에는 익숙하지 않다.
- 시스템 구축 담당자: 주소·단위·스케일을 확인하고 파일을 다른 구축 환경에서 재사용한다.
- 구매 담당자: 왜 추가 장비가 필요한지, 기존 장비로 가능한지, 무엇을 확인해야 하는지 이해해야 한다.

## 첫 버전에서 제공하는 흐름

1. **설비 정보**: 이름·제조사·모델·위치·일련번호·목적. AAS/설비 식별자를 생성하고 이름이 바뀌어도 유지한다.
2. **연결 방식**: 지원 프로토콜·IP·포트·국번·주기. 모르는 항목을 명시적으로 선택할 수 있다. 물리 신호 종류와 입력 수를 확인한다.
3. **수집할 신호**: 주소·자료형·단위·워드 순서·배율·보정·선택적 의미 식별자. 원시 Modbus 주소와 Modicon 주소를 구분해서 안내한다.
4. **검토·활용**: 파일 생성에 필요한 정보와 수집 적용에 필요한 정보를 구분한다. 수정 버튼은 해당 단계/필드로 이동한다. 파일 생성, 설정 미리보기, 설정 적용을 각각 제공한다.
5. **현장 검증**: 기존 장치 연결 테스트 → 변수 값 읽어보기 → 수집 작업 선택/시작. 업로드만으로 장치에 접속하지 않는다.

초안은 서버 PC의 `data/aas/project.json`에 자동 저장한다. 새로 열면 복원하고 서로 다른 창이 오래된 초안을 덮어쓰는 것은 revision 비교로 막는다. ‘새 설비’는 현재 초안을 바꾸며 이전 초안이 필요하면 AASX로 먼저 내보내도록 안내한다. 첫 버전은 PC당 초안 1개다.

입력 후에는 큰 안내 영역을 접어 실무 화면에 집중하게 한다. 색상만으로 상태를 표현하지 않고 텍스트와 기호를 함께 쓴다. 라벨·키보드 이동·초점 표시·모바일 레이아웃·기존 밝은/어두운 테마를 지원한다. 외부 CDN이나 글꼴이 필요하지 않다.

## AASX 처리 범위

내보내기는 AAS 3.x JSON Environment를 OPC ZIP 패키지로 저장한다. 현재 작성하는 서브모델은 `AssetIdentity`, `CollectorConnection`, `SignalDefinitions`이며 **앱에서 정의한 모델**이다. IDTA Digital Nameplate / Asset Interfaces 공식 템플릿 구현으로 광고하지 않는다.

수집 프로필 의미 식별자: `urn:plc-collector:aas:connection-profile:1`. `CollectorConnection.CollectorProject` Blob 안에 버전이 있는 JSON 매핑을 포함한다. 프로필을 포함한 단일 설비 파일은 입력값을 복원한다. 프로필과 AAS 설비 ID 및 서브모델 참조가 다르면 거부한다. 해당 프로필은 신뢰할 수 있는 실행 코드가 아닌 사용자 입력으로 다시 검사한다.

외부 AASX는 관계 파일을 따라 JSON 모델을 찾는다. 앱 프로필이 없는 경우 설비/서브모델 목록과 식별자를 확인한 뒤 사용자가 설비를 선택하고 직접 통신·신호 정보를 입력한다. 외부 파일 전체를 수정해 다시 저장하는 기능은 아니다. 직접 매핑을 시작하면 새로운 앱 프로젝트로 작성하며 외부의 추가 서브모델·첨부파일은 재출력하지 않는다.

현재 제한: 업로드 3MB, 압축 해제 합계 16MB, ZIP 항목 256개, AAS 100개, 서브모델 256개, 프로젝트 신호 100개. JSON 모델 1개만 자동 해석한다. AAS XML, AAS 2.x, 복수 JSON 모델 패키지, 서명 검증·암호화는 아직 지원하지 않는다. 제한은 UI/API에 명시하고 지원하지 않는 파일을 묵시적으로 손실 변환하지 않는다.

## 장비 구성 제안 원칙

- 기존 Ethernet과 지원 통신이 있으면 기존 경로를 우선한다. 추가 구매를 단정하지 않는다.
- 4–20mA / 0–10V를 직접 확보해야 하는 경우 ADAM-6017을 조건부 후보로 제시한다. 8 AI 기준 최소 수량을 올림 계산한다. PLC에서 이미 읽는 값인지, 절연·전원·배선·스케일·채널당 속도·모델 세대별 레지스터 맵을 확인하도록 한다.
- RTD / 열전대 / 디지털 접점은 신호 전용 I/O 검토로 분기한다. ADAM-6017의 전압/전류 입력을 직접 호환으로 처리하지 않는다.
- Ethernet이 없는 PLC는 제조사·CPU 정확한 형번·펌웨어·슬롯을 확인하기 전 특정 모듈 형번을 확정하지 않는다. LS 자료는 FEnet 검토 근거이며 모든 제조사의 PLC에 호환된다는 뜻이 아니다.
- 가격·재고·발주·전기 설계는 첫 버전에 포함하지 않는다. 자료 출처는 `docs/REFERENCES.md`에 기록한다.

## 완료 판단과 다음 제품 단계

첫 버전 완료 기준은 가상 설비로 작성→저장/복원→AASX 왕복→매핑 점검→기존 설정을 보존한 추가가 동작하는 것이다. ‘오류 없는 상용 서비스’로 표현하지 않는다. 실설비 검증과 제3자 AAS 도구 교환 검증이 남아 있다.

다음 단계는 공식 IDTA 템플릿을 고정 버전으로 도입하고 의미·카디널리티 검증을 추가하는 것이다. 이후 AASX 라이브러리/버전 관리, 설비별 근거 첨부, 승인된 매핑 템플릿, CPU-모듈 호환 카탈로그를 확장한다. 다중 고객 서비스로 확장할 때에는 고객별 데이터 분리·역할·접근 제어·작업 이력과 현장 에이전트 구조가 먼저 필요하다. Python TCP 수집기를 인터넷 사이트에 그대로 노출하는 배포는 제공하지 않는다.
